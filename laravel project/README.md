# Medical Case Management (Intern Assignment)

A Laravel + MySQL case-management starter using Blade, session authentication, Sanctum token API authentication, policies, Form Requests, seeders, factories, and feature tests. **All data is dummy data.**

## Requirements
- PHP 8.2+
- Composer
- MySQL 8+ or compatible MariaDB
- Node.js/npm is not required for the simple Blade UI

## Setup
This repository is a source starter intended to be placed into a fresh Laravel 11 project, so framework bootstrap files and vendor dependencies are generated by Composer rather than bundled.

1. Create a Laravel project:
   ```bash
   composer create-project laravel/laravel medical-case-management "^11.0"
   cd medical-case-management
   ```
2. Copy the contents of this assignment ZIP into that project folder, allowing files to merge/replace when prompted.
3. Install Sanctum:
   ```bash
   composer require laravel/sanctum
   php artisan install:api
   ```
   If `install:api` asks to publish API scaffolding, accept it. Ensure `routes/api.php` from this bundle is present.
4. Create a MySQL database named `medical_case_management`.
5. Copy `.env.example` to `.env`, then set `DB_DATABASE`, `DB_USERNAME`, and `DB_PASSWORD`.
6. Run:
   ```bash
   php artisan key:generate
   php artisan migrate:fresh --seed
   php artisan serve
   ```
7. Open `http://127.0.0.1:8000`.

## Tests
```bash
php artisan test
```
Tests use Laravel's testing database configuration; set up a test database or configure SQLite in-memory in `phpunit.xml`.

## API
Send `Accept: application/json` on API requests.
- `POST /api/login` — `{ "email": "...", "password": "..." }`
- `POST /api/logout` — bearer token required
- `GET /api/cases` — bearer token required; optional `search`, `status`, `per_page`
- `POST /api/cases` — Admin only
- `GET /api/cases/{id}` — Admin or Viewer
- `PUT /api/cases/{id}` — Admin only
- `DELETE /api/cases/{id}` — Admin only

Example: log in, copy `data.token`, then send `Authorization: Bearer TOKEN`.

## What is included
- Role-based web screens and API authorization
- Case dashboard, searchable/filterable paginated list, create/edit, detail, delete
- Backend validation, unique case number, indexed status, creator foreign key
- Two seeded users and 25 dummy cases
- Feature tests and database/traceability/deployment notes

## Assumptions and known limitations
- Case number is entered by an Admin and must be unique (example `CASE-0001`).
- Viewer can view cases but cannot create, edit, change status, or delete.
- The UI uses simple CSS and Blade; no frontend build is needed.
- API list responses use Laravel pagination nested inside the consistent `data` field.
- This starter ZIP does not contain Composer's `vendor/` directory; install dependencies using the steps above.
- Medical data is fictional only. This is an educational demo, not a validated medical device system.
